# Security Baseline

AgriNex AI is a public, no-account website and API. Registration, login, authentication, user accounts, and user-owned records are not required. Do not add Supabase Auth or account tables. CORS controls browser origin access only; it does not authenticate callers.

Secrets are environment variables and are never committed, returned by APIs, logged, or shipped to the frontend. Future AI and provider credentials belong only in the FastAPI environment. CORS uses an explicit environment-derived origin allowlist, rejects wildcards, and disables credentialed requests. Validate requests with FastAPI/Pydantic and validate external responses before presenting or caching them.

Request browser geolocation only after a farmer explicitly chooses location detection, explain its use, and handle denial gracefully. Manual location entry must remain available. Keep preferences and optional session history in browser-local storage by default, avoid sensitive content, and provide clear/delete controls if history is added. Do not transmit local history to the backend without a reviewed requirement.

The Phase 03 backend generates request IDs, uses safe response envelopes, applies configurable provider timeouts, and maps known provider failures to non-sensitive errors. JSON logs include request ID, method, matched route template, status, duration, and safe error type; they exclude request/response bodies, query values, client IPs, and credentials. Weather and market caching is process-local, bounded, expires entries, and uses hashed request keys. AI question content is not cached. Default provider adapters return 503 without making network calls.

For Phase 04, all Open-Meteo calls originate in FastAPI and use an allowlisted official HTTPS host. Coordinates are bounds-validated and provider JSON is parsed by typed models. Provider credentials are not required or exposed. Browser geolocation is requested only by an explicit user action and denial/failure falls back to manual coordinates. The cache stores provider responses only after success, never failed responses or personal logs.

For Phase 05, `DATA_GOV_IN_API_KEY` is server-only and must never be placed in browser environment variables or logs. The upstream host and resource ID are fixed to the verified data.gov.in AGMARKNET resource. Query filters and page sizes are bounded, provider JSON is strict, and malformed records are discarded rather than corrected. No GPS or other personal location capability is used for mandi search.

For Phase 06, `GEMINI_API_KEY` is server-only. The assistant sends only recent conversation text and explicitly supplied farm coordinates/context, not browser identity or GPS data without user-provided context. It does not log complete conversations or persist a memory. Tool calls are allowlisted and arguments are revalidated server-side. Responses are constrained to JSON/Pydantic schemas, provider credentials and internal prompts are never returned, output is bounded, and public chat has configurable body-size and per-minute limits. Gemini free-tier quota and cost limits must be considered insufficient by default for public production traffic.

Before enabling public or costly integrations, add and verify request-size limits, rate limits, provider quotas, and abuse monitoring; configure operational monitoring and provider-specific error translation. CORS alone is not protection against direct API clients. If a database is later justified, use least-privilege service access and store only required operational/source data; no user-row RLS design is needed for the current account-free scope. This baseline is not a compliance or production-readiness claim.
